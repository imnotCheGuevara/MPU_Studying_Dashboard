# Campus Dashboard 本地桌面学习助手：项目需求书

版本：1.2
状态：DeepSeek 公告分类已完成；邮箱扩展已移除；最终集成已授权，试运行待发布候选
平台：macOS 与 Windows，本地单用户应用；Windows 版不含 iCloud 或任何外部日历集成

## 1. 项目概述

Campus Dashboard 是一个仅供个人使用的本地桌面应用。它汇总学校 SIweb 和 Canvas 中与学习有关的信息，转换为统一数据模型，并在 macOS 与 Windows 上提供今日总览、日程、任务、公告、提醒与同步状态。macOS 版可把经确认的项目写入专用 Apple 日历；Windows 版只保留应用内 Today/Schedule，不连接 iCloud、Outlook 或其他外部日历。

第一阶段目标是建立可靠、合规、可解释的信息连接和同步链路。AI 仅用于整理已经合法同步到本地的 Canvas 内容，不承担登录、网页访问、来源写入或日历操作。第二阶段才扩展为 AI 学习规划。

## 2. 项目原则与边界

### 2.1 第一阶段必须实现

- 验证并实现至少一种合规、稳定的 SIweb 课程信息输入方式。
- 验证并实现 Canvas 作业、测验类事项和公告同步。
- 支持手动刷新和目标间隔为每小时的自动同步。
- 提供今日总览、日程、任务、公告、AI 确认队列和设置页面。
- 提供本地数据缓存、同步记录和安全凭证存储。
- 提供可配置的本地通知。
- 仅向应用管理的专用 Apple 日历写入事件，并验证 iCloud 到 iPhone 的同步。
- 使用受控 AI 辅助理解 Canvas 中不一致的课程组织、命名和发布习惯。
- 所有来源、日历、通知和 AI 操作均可追踪、可解释、可安全重试。

### 2.2 第一阶段明确不做

- 不自动提交作业、测验、请假或修改学校系统资料。
- 不自动修改 Canvas 的完成、已读或订阅状态。
- 不绕过登录、验证码、多因素验证、访问限制或学校规则。
- 不做多人账号、云端用户系统、手机原生应用或公开发布。
- 不让 AI 自动登录、抓取网页、决定删除数据，或直接改动学校系统和 Apple 日历。
- 不改动用户的个人、家庭、共享或订阅日历。
- 不完整解析测验题目、答案、成绩或其他与日程汇总无关的数据。
- 不承诺 Mac 休眠或关机时仍严格按整点执行同步。

### 2.3 不可违反的安全规则

1. 学校系统连接器在第一阶段只读。
2. 本地完成、已读、隐藏和优先级状态与来源状态分开保存。
3. 应用只能管理由本应用创建且具有有效本地关联记录的日历事件。
4. 不能仅因一次同步未返回某条记录就删除本地数据或日历事件。
5. 所有非官方字段直接提供的日期均属于推断日期，未经人工确认不得进入 Apple 日历或触发截止提醒。
6. AI 输出不能直接调用来源连接器、EventKit 或通知服务。

## 3. 第一阶段成功标准

第一阶段按三个层次验收：

### 3.1 功能完成

- Canvas 与 SIweb 的可行性结论、授权方式、字段和限制均有记录。
- 本地界面、存储、同步、日历、通知和 AI 确认队列达到各任务验收标准。
- 自动化测试和假数据集成测试通过。

### 3.2 设备集成完成

- 在真实 Mac 上创建、更新和取消应用管理的日历事件。
- 同一事件通过 iCloud 正确同步到真实 iPhone。
- 不产生重复事件，不修改或删除非本应用事件。

### 3.3 运行验收完成

- 连续七天真实试运行。
- 无日历误删、无未经确认的 AI 日期写入、无重复截止通知。
- 来源失败相互隔离，失败原因可解释，恢复后能够补偿同步。
- 同步成功率达到试运行前约定的目标；建议目标为 Mac 在线且后台同步已启用期间不低于 99%。

只有以上三个层次均完成，第一阶段才视为正式完成。

## 4. 数据来源、优先级与准入门槛

Canvas 和 SIweb 分别按以下顺序验证：

1. 官方 API 或学校授权接口；
2. 官方导出数据，例如 ICS、CSV 或正式课表文件；
3. 经学校政策允许、基于用户本人已登录会话的稳定页面读取；
4. 对已经合法获取的 Canvas 非结构化内容使用 AI 辅助分类和提取。

第 4 项不是连接方式，不得用于获取尚未同步的数据。

### 4.1 连接器准入记录

每个来源在实现前必须完成一份连接评估，至少记录：

- 学校、系统名称、实例 URL 和系统版本（如可知）；
- 官方文档和学校使用政策；
- 授权方式、令牌有效期、刷新和撤销方式；
- 可读取字段、不可读取字段和个性化字段；
- 分页、增量读取、频率限制和退避要求；
- 时区、课程学期和用户身份处理方式；
- 401、403、404、429、服务器错误、网络中断和响应格式变化等失败模式；
- 首次全量同步和后续增量同步策略；
- 来源删除、取消和缺失的判定能力；
- 凭证保存位置和日志脱敏要求。

未完成评估的连接器不得进入正式实现。

### 4.2 Canvas 准入标准

已确认的实施基线：Canvas 数据通过 API 获取，不使用网页爬虫作为 Canvas 的主要连接方式。

优先使用学校允许的 OAuth 2.0。若学校明确允许个人 API Token，可在仅个人使用的原型阶段支持 Token，但必须存入 macOS Keychain，且不得进入日志、数据库、普通配置或示例数据。

Canvas 第一阶段至少需要验证：

- 当前学生可访问的课程及课程上下文；
- Assignment 及对当前用户生效的 due date override；
- Classic Quiz、New Quiz 或以 Assignment/LTI 形式出现的测验类事项；
- Announcement 标题、发布时间、正文摘要和来源链接；
- 分页、限流响应和必要的重试策略；
- 课程、作业和公告的稳定来源 ID。

如果只能获得 Canvas ICS，允许把它作为课程和截止事项的降级输入，但 ICS 不能单独满足“公告与描述整理”的完整验收要求。

测验同步的第一阶段定义为：正确同步当前学生可见的、具有学习行动或截止意义的测验类事项。第一阶段不要求获取题目、答案或完整测验内部结构。

### 4.3 SIweb 准入标准

已确认的实施基线：学校官网/SIweb 允许使用爬虫技术读取当前用户有权访问的学习信息。连接器为只读，不执行表单提交或学校系统写入。

在实现 SIweb 连接器前，必须确认：

- 学校名称与 SIweb 的准确登录 URL；
- 是否存在 API、ICS、CSV、PDF 或其他官方导出；
- 是否使用 SSO、MFA、验证码或短期会话；
- 课程 ID、名称、代码、上课时间、地点和取消信息是否稳定可读；
- 允许自动读取的页面范围、访问频率和账号会话边界；
- 页面结构变化和会话过期时的失败表现。

爬虫连接器必须遵守以下约束：

- 只读取用户在普通浏览器中有权查看的页面；
- 复用经用户主动登录获得的合法会话，或使用学校允许的认证流程；
- 不自动填写或提交会改变学校系统状态的表单；
- 不绕过 SSO、MFA、验证码、robots/访问限制或频率控制；
- 使用可配置的请求间隔、指数退避和并发上限；
- 优先解析稳定的语义标记、链接和数据属性，避免依赖脆弱的视觉位置；
- 保存页面解析器版本和必要的内容哈希，不保存完整登录页或敏感无关内容；
- DOM 或字段契约变化时停止该来源写入并报告“页面结构已变化”，不得静默生成错误课程数据；
- 保留 ICS/CSV 手动导入作为爬虫暂时失效时的可选降级方案。

## 5. 推荐技术方案

第一阶段推荐使用原生 macOS 技术栈：

- Swift + SwiftUI：桌面界面和状态展示；
- URLSession：官方 API 与文件下载；
- SQLite（可使用轻量封装）或 SwiftData：本地结构化数据；
- macOS Keychain：令牌、Cookie 或其他允许保存的凭证；
- EventKit：Apple 日历；
- UserNotifications：本地通知；
- Service Management：用户可管理的登录项或后台同步服务；
- OSLog：结构化、脱敏日志。

连接器、领域模型、同步编排、数据库、日历、通知和 AI 必须通过协议隔离，便于使用假数据测试，避免 UI 直接依赖第三方响应。

## 6. 统一数据模型

所有来源数据先保存为原始记录，再转换为统一模型。界面、通知、AI 和 Apple 日历只读取统一模型或明确的确认队列，不直接依赖连接器响应。

所有来源对象使用 `(source_account_id, source_object_id)` 作为稳定复合唯一键。本地生成的 UUID 仅作为应用内部标识。

### 6.1 核心对象

| 对象 | 必要字段 |
| --- | --- |
| 来源账号 SourceAccount | 内部 ID、来源类型、实例 URL、显示名、授权状态、能力标记、最近成功时间 |
| 课程 Course | 内部 ID、来源账号、来源 ID、课程名、课程代码、学期、时区、原始链接、来源状态、首次/最后发现时间、更新时间 |
| 课程时段 CourseMeeting | 内部 ID、课程、来源 ID、开始/结束时间、是否全天、地点、重复规则、取消状态、更新时间 |
| 学习任务 LearningTask | 内部 ID、来源账号、来源 ID、课程、标题、官方类型、标准化类型、官方截止时间、开放/锁定时间、原始链接、来源状态、更新时间 |
| 本地用户状态 LocalUserState | 对象 ID、对象类型、本地完成、已读、隐藏、本地优先级、修改时间 |
| 公告 Announcement | 内部 ID、来源 ID、课程、标题、发布时间、更新时间、摘要、内容哈希、原始链接、来源状态 |

### 6.2 日期规则

- `official_due_at` 只保存来源官方字段对当前用户生效的截止时间。
- `suggested_complete_at` 可由用户或 AI 提议，但不能覆盖官方截止时间。
- 所有日期保存原始时区信息并规范化为可比较的时间值。
- 无明确时区或从文本推断的时间必须进入人工确认。
- 全天日期和具体时间必须分开表达，禁止用本地午夜假装精确截止时间。

### 6.3 状态规则

- 来源状态、本地完成状态、AI 判断状态相互独立。
- 用户本地完成或已读绝不写回学校系统。
- 来源取消不会自动清除用户的本地历史记录；默认软删除并保留审计信息。

## 7. 桌面应用页面

### 7.1 今日总览

- 主体为当前周课表：横向固定表达周一至周日，纵向表达早上至晚上的真实时间轴；
- 课程块按真实开始/结束时间比例定位和显示时长，不得压缩为无时间关系的等高列表；
- 同一时间重叠的课程使用确定性的并列布局，不能互相完全遮挡；跨出可视时间范围的课程必须安全裁切并保留可理解的时间信息；
- 清楚标识当前日期和当前时间，并提供上一周、下一周和回到本周的导航；
- 未读公告作为右侧栏显示，保留课程归属、发布时间、原始来源链接和本地已读操作；
- SIweb、Canvas、后台同步状态、上次成功时间、手动刷新及同步进度以不抢占周课表主体的紧凑形式保留；
- 真实数据库为空、来源失败或权限不可用时显示真实空态/错误态，绝不回退到虚构课程。

### 7.2 日程

- 使用符合 macOS 习惯的空间化日历界面，至少提供日、周、月三种视图以及上一时段、下一时段和回到今天的导航；
- 日/周视图具有日期头、全天区域、纵向时间刻度、当前时间指示和按真实时间/时长定位的事件块；重叠事件必须并列显示；
- 月视图按真实月份网格和日期单元格表达跨周关系，并允许进入选定日期的详细日程；
- 课程时段、官方截止事项和已确认的推断截止事项使用可区分但一致的视觉语义；未确认推断不得出现为正式事件；
- 应用内日历中的 Assignment 与 Quiz 官方截止事件使用红色，并同时保留明确的“官方截止”文字或图标，不能仅靠颜色传达；已确认推断日期使用不同视觉语义。Apple 日历仍遵循专用日历的统一颜色，不承诺单事件独立着色；
- 支持课程、来源和事件类型筛选，选中事件后可查看时间、地点、状态和原始来源链接；
- 取消、变更、全天事项、无日期事项和同步异常必须有明确且可访问的表现；
- 设计可以借鉴通用 macOS 日历交互，但不得复制 Apple 商标、专有插图、私有资源或像素级产品外观。

### 7.3 任务

- 按今天、本周、未来、逾期和无日期分组；
- 按课程、官方类型、标准化类型和确认状态筛选；
- 同时显示官方截止时间与建议完成时间；
- 支持本地完成和本地优先级；
- 明确区分官方信息与 AI/用户建议。

### 7.4 公告

- 按课程分组；
- 支持本地标记已读；
- 显示发布时间、摘要和原始链接；
- 显示 AI 提取的行动项，但推断日期必须进入确认队列。

### 7.5 AI 确认队列

- 展示原始内容摘要、来源链接、AI 结果、可信度和判断依据；
- 区分类型归一化、重复归并、行动项和日期推断；
- 支持确认、修正、拒绝和撤销确认；
- 只有确认后的推断截止事项才可进入日历和截止提醒；
- 用户可查看原始值、AI 值和最终采用值。

### 7.6 设置

- 数据源实例、授权状态、能力与重新授权；
- 自动同步开关和目标频率；
- 后台项目状态及系统设置入口；
- 通知总开关、课程级开关、提醒提前量和静默时间；
- 专用 Apple 日历创建、选择、校验和修复；
- AI 辅助开关、外部服务数据说明和人工确认默认策略；
- 本地数据导出、清理和重新建立索引；
- 脱敏诊断信息查看与导出。

### 7.7 本地化

- 系统 UI 完整支持英文和简体中文；语言切换后无需重启即可一致更新当前界面；
- 简体中文覆盖日期、月份、星期、相对时间、状态、错误提示、同步说明、按钮、菜单、对话框、工具提示、空状态和无障碍标签；
- 用户可见状态不得直接显示未本地化的枚举 `rawValue`、开发占位文本或仅英文错误描述；
- 日期和星期格式使用所选语言对应的 Locale、Calendar 和时区，不依赖固定英文字符串；
- 课程名称、课程代码、教师发布的公告标题/正文、任务标题、地点及其他来源原文默认保持原样；应用不得把机器生成或字典替换的文字冒充来源翻译；
- 原始来源链接和稳定来源身份不因语言切换而变化。

## 8. 同步架构与流程

### 8.1 标准同步管线

每个来源独立执行以下流程：

```text
连接器读取
→ 保存最小必要的原始快照
→ 确定性规范化
→ 比较并生成变更集
→ 在数据库事务中写入统一模型和同步记录
→ 生成 Calendar/Notification Outbox
→ 独立执行日历与通知副作用
→ 记录结果并按策略重试
```

日历或通知失败不得回滚已经成功保存的来源数据。Outbox 必须支持幂等执行和安全重试。

### 8.2 调度语义

- 默认目标同步间隔为 60 分钟，可在设置中关闭或调整。
- “每小时”不表示 Mac 睡眠、关机或用户未登录时严格整点执行。
- 当用户已登录、Mac 可运行且后台同步已启用时，尽量按目标间隔执行。
- 从睡眠、离线或后台服务禁用状态恢复后，应在五分钟内触发补偿同步。
- 用户手动刷新可立即触发，但相同来源同一时间只允许一个活动同步运行。
- 手动同步和自动同步使用相同的业务管线。

### 8.3 故障隔离与重试

- SIweb 与 Canvas 独立运行，一个来源失败不得阻塞另一个来源。
- 401/403 默认停止自动重试并提示重新授权或权限不足。
- 429 和暂时性服务器错误采用带抖动的指数退避，并尊重服务端重试提示。
- 网络离线不视为授权失败，恢复后执行补偿同步。
- 连续同类失败只通知一次；状态恢复后允许发送一次恢复通知。
- 日志只记录错误类别、请求上下文和脱敏摘要，不记录令牌、Cookie 或完整敏感响应。

### 8.4 首次同步

- 首次同步建立基线，不把所有历史记录都通知为“新作业/新公告”。
- 默认只为未来课程和未到期事项安排提醒。
- 首次同步完成后显示导入数量、忽略数量和能力限制。

## 9. 去重、更新与删除规则

### 9.1 去重

- 优先使用来源稳定 ID，不使用标题作为唯一键。
- 重复同步不得产生重复课程、任务、公告、日历事件或通知。
- AI 可以建议关联或重复，但不能删除或合并原始来源对象。

### 9.2 更新

- 来源中的标题、时间、地点、官方类型或状态变化必须更新同一统一对象。
- 每次重要变化生成 ChangeRecord。
- 日历事件通过 CalendarBinding 更新原事件，不通过标题搜索并修改。
- 通知计划在截止时间变化后重新计算，并取消旧的未触发通知。

### 9.3 删除与取消证据

按以下优先级判断来源取消：

1. 来源明确返回 deleted、cancelled、unpublished 或等价状态；
2. 官方完整快照中连续两次缺失，且两次同步均完整成功；
3. 用户人工确认来源事项已经取消。

以下情况不得自动视为删除：

- 单次请求失败；
- 分页未完成；
- 增量接口未返回该对象；
- 权限变化导致不可见；
- AI 从自然语言推断可能取消。

满足删除条件后，只能软删除本地对象，并只删除具有有效 CalendarBinding 且确认由本应用创建的对应事件。

## 10. Apple 日历与 iCloud

### 10.1 权限

由于应用需要读取、核对、更新和删除自己创建的事件，必须申请 EventKit 完整事件访问权限。权限申请必须由用户主动启用日历同步的操作触发，并清楚解释用途。

拒绝权限后，应用其他页面和来源同步仍须可用。

### 10.2 专用日历身份

应用只管理用户明确选择或由应用创建的专用日历。默认名称为 `Campus Dashboard`，但名称不是唯一身份。

必须保存并校验：

- EventKit calendar identifier；
- calendar source identifier；
- 来源类型和账号显示名；
- 应用生成的内部日历 UUID；
- 日历是否允许内容修改；
- 最近一次成功校验时间。

若 calendar identifier 因完整同步而失效，应用可使用来源、名称和应用标记寻找候选，但不得自动认领无法唯一确认的同名日历。存在多个候选时必须要求用户重新选择。

### 10.3 iCloud 前提

- 用户必须选择可写的 iCloud 日历来源，才能把状态显示为“iPhone 同步已配置”。
- 如果仅选择本机日历，应明确显示“仅此 Mac”。
- 应用负责通过 EventKit 保存事件，但不把 iCloud 到达时延描述为应用可严格保证的即时同步。

### 10.4 事件规则

- 课程时段、作业截止和测验截止可创建事件。
- 不同步公告、无明确日期事项和未确认的 AI 推断事项。
- 经人工确认的公告课时调整或考试时间可通过普通同步服务创建、更新或取消绑定事件；高可信度本身不构成写入授权。
- 考试在应用日历中必须使用兼顾色觉无障碍的专用颜色和非颜色标签/图标。Apple Calendar 的同一日历不保证逐事件颜色，因此以明确的考试类型标记、标题或备注区分，不为此新建或修改其他日历。
- 事件包含课程、时间、地点、原始链接和不含敏感信息的应用关联标记。
- 来源变更时更新同一事件。
- 来源取消时仅删除应用创建且绑定有效的对应事件。
- 用户移动或编辑应用事件后的策略必须明确；默认以下一次官方同步恢复应用管理字段，同时不触碰其他事件。
- 禁止修改专用日历之外的任何事件。

### 10.5 真实设备验收矩阵

至少验证：

| 场景 | Mac 预期 | iPhone 预期 |
| --- | --- | --- |
| 创建课程事件 | 只在专用日历出现一次 | 同步后出现一次 |
| 修改时间/地点 | 更新原事件 | 原事件被更新 |
| 官方取消 | 只删除绑定事件 | 对应事件消失 |
| 重复同步 | 不新增副本 | 不新增副本 |
| 同名用户日历 | 不修改、不认领 | 不受影响 |
| EventKit 标识失效 | 安全恢复或要求重选 | 无误删 |
| iCloud 暂时离线 | 本地记录待同步状态 | 恢复后最终一致 |

## 11. AI 辅助 Canvas 整理

### 11.1 目标

AI 用于把已经合法同步到本地的 Canvas 内容整理为一致、可行动的学习视图。AI 不是连接器、调度器、日历服务或学校系统操作工具。

### 11.2 适用场景

- 标准化不一致的作业、测验、阅读或公告命名；
- 从公告或描述中提取关键要求和准备事项；
- 在官方类型不足时建议事项类型；
- 识别同一事项在多条记录中的关联关系；
- 同步后生成极短的今日变化摘要。

### 11.3 处理顺序

1. 使用来源官方类型、官方日期和确定性规则；
2. 对必要的最小文本执行 AI 分析；
3. 使用严格 JSON Schema 验证输出；
4. 由策略引擎标记自动采用、本地候选或需要确认；
5. 用户确认推断字段；
6. 普通同步服务根据最终统一模型生成日历和通知操作。

AI 无权直接调用 EventKit、通知服务或来源连接器。

### 11.4 AI 输入

- Canvas 标题、官方类型、课程、官方截止时间；
- 公告摘要和任务描述中的最小必要文本；
- 来源、课程上下文、语言和输出字段要求；
- 已知课程、已有任务和公告的必要摘要，用于关联与避免重复。

禁止输入：

- 密码、访问令牌、Cookie；
- 完整登录页面；
- 与当前整理任务无关的个人信息；
- 不必要的附件全文或历史数据。

### 11.5 AI 输出

- 建议事项类型；
- 标准化标题；
- 建议所属课程；
- 关键要求；
- 官方日期的复述与建议完成时间的明确区分；
- 重复或关联事项候选；
- 可信度、判断依据和冲突标记；
- 简短的同步变化摘要。

### 11.6 控制规则

1. AI 不得修改 `official_due_at`。
2. AI 生成的日期必须标记为 inferred。
3. 所有 inferred 日期，无论可信度高低，必须人工确认后才能进入 Apple 日历或截止通知。
4. 类型和标题标准化可作为本地展示候选，但原始内容和来源链接必须保留。
5. AI 只能建议重复关系，不得删除、覆盖或物理合并来源记录。
6. 用户可关闭 AI，查看、修正或拒绝结果。
7. AI 失败不能阻塞来源同步、确定性规则、日历同步或通知。
8. 若使用外部 AI 服务，首次启用前必须展示提供方、传输字段类别、保留策略和关闭方式。
9. `other`、冲突和提供方不可用时保留的确定性结果同样必须允许用户修正；修正可撤销且不得写回 Canvas。
10. 用户修正属于带标签的本地监督反馈。应用可用版本化、可解释的课程级规则或重排序改善后续结果，但不得静默改写无关历史、上传修正历史或在未另行同意时训练远程模型。

### 11.7 AI 可追踪性与评测

每次解析保存输入哈希、模型/提供方、Prompt 版本、Schema 版本、输出、可信度、依据和最终人工处理结果。

上线前使用脱敏样本评估：

- 类型分类准确率；
- 重复事项误合并率；
- 截止时间错误提取率；
- 冲突和不确定事项召回率；
- 未确认推断进入日历或提醒的次数，必须为零。
- 按分类报告 precision、recall 与 F1，并保存修复前基线、独立回放样本和修复后结果；不得用训练/修正样本本身冒充泛化提升。
- 记录提供方失败时确定性规则恢复率、用户修正率、重复事件率，以及具有样本量和方法说明的任务处理耗时对比；只可报告真实测得的简历指标。

### 11.8 DeepSeek Canvas 公告分类扩展

该扩展只分析已经由 Canvas API 合法同步到本地、且用户明确允许发送的公告最小文本。固定分类为：

- `course_schedule_change`：课时、上课地点、停课、补课或教学安排调整；
- `assignment_deadline`：作业要求、提交安排或作业截止时间；
- `exam_time`：考试、测验或 Quiz 的日期、时间、地点与准备要求；
- `other`：不属于以上类别或信息不足。

一条公告可以包含零到多个学习信号，同时保存一个主要分类。每个非 `other` 信号必须带有最短证据摘录、可信度、冲突标记和来源公告关联。分类不得伪造 Canvas 官方类型。

DeepSeek 接入规则：

1. 默认关闭。首次启用前展示提供方、经审查的隐私/条款日期、跨境处理提示、字段类别、关闭和清理方式，并取得可撤销同意。
2. API Key 只存 Keychain；不通过聊天、普通设置、日志或数据库传递。
3. 只允许固定 HTTPS API 地址、固定模型配置和严格 JSON Schema；禁用 Web Search、工具调用、文件/图片上传和远程 URL 获取。
4. 默认遵循 macOS 系统代理。若已证明系统代理导致 DeepSeek TLS 失败，可提供默认关闭的“仅 DeepSeek API 直连”选项；必须由用户明确开启，只能绕过 `api.deepseek.com` 的代理解析，不得修改或关闭 FlClash/VPN，也不得影响其他应用或主机。
5. 输入只包含公告标题、必要正文摘录、最小课程上下文、语言及 Schema 指令；不包含 Canvas URL、令牌、Cookie、学生身份、作者邮箱、附件或无关历史。
6. 公告正文中的指令一律视为待分类数据，不能改变系统提示、Schema、权限或调用目标。
7. 公告中提取的日期均为 `inferred`。即使高可信度，也必须人工确认后才可形成正式日历事件或截止通知；官方 Canvas 日期始终优先。
8. 空响应、截断、限流、超时、非法 JSON、未知字段、模型更换或服务不可用均安全失败，不阻塞 Canvas 同步，也不产生外部副作用。
9. 明确的中英文停课/取消措辞（例如 `class cancellation`、`class cancelled`、`停课`、`课程取消`）必须先由确定性规则识别为 `course_schedule_change`；DeepSeek 不可用时不得退化为无理由的 `other`。
10. 高可信度只决定本地候选展示优先级，不能越过 inferred 日期人工确认。确认后由普通同步服务幂等更新应用日历和专用 Apple 日历；撤销确认应安全撤销对应绑定变更。

## 12. 通知规则

### 12.1 可通知事件

- 基线同步完成后首次出现的新作业、新测验和新公告；
- 官方截止时间或已确认推断时间之前的提醒；
- 上课前提醒；
- 连续同步失败；
- 来源或日历从失败恢复；
- 可选的待确认事项汇总。

### 12.2 默认提前量

- 截止前 24 小时、3 小时、1 小时；
- 上课前 15 分钟；
- 均可配置或关闭。

### 12.3 去重与重调度

通知唯一键至少包含关联对象、通知类型、目标时间和规则版本。重复同步不得重复安排或投递同一通知。

当截止时间变化、事项取消、用户关闭课程通知或进入新的策略版本时，必须取消旧通知并重新计算。

### 12.4 静默规则

- 支持总开关、课程级开关和夜间静默；
- 静默期间的普通提醒默认延后到静默结束或合并摘要；
- 如果延后后已经失去意义则取消，而不是补发过期提醒；
- 连续同类同步失败只通知一次，避免通知风暴。

## 13. 本地安全与隐私

- 账号凭证、令牌和允许保存的会话信息只存入 macOS Keychain。
- 不在源码、日志、数据库、普通配置或示例数据中保存敏感凭证。
- 应用启用 App Sandbox，并只申请实现功能所需的权限。
- 数据库、缓存和日志目录使用用户级访问权限。
- 日志对 URL 参数、账号标识、正文和错误响应进行必要脱敏。
- 原始来源记录只保存实现功能和解释变化所需的最小内容。
- 本地缓存、同步日志、AI 解析记录和通知记录支持按类别清理。
- 清理凭证和清理历史数据必须分开确认，避免误操作。
- 清理本地数据不能自动删除 Apple 日历事件；若用户希望删除应用事件，应提供独立、可预览的清理动作。
- 外部 AI 默认关闭；启用前明确说明传输的数据类别，并默认只发送最小必要的结构化或脱敏内容。
- 示例数据必须完全虚构，不得由真实学生数据简单改名得到。

## 14. 可观测性与错误说明

应用至少显示：

- 各来源当前状态和最近成功时间；
- 最近一次同步读取、新增、更新、取消和跳过数量；
- 数据库、AI、日历、通知各阶段状态；
- 面向用户的简明错误和建议动作；
- 可导出的脱敏诊断摘要。

错误必须按类别表达，例如：未授权、权限不足、频率限制、网络离线、来源响应变化、解析失败、日历权限被撤销、专用日历丢失、后台同步被禁用。不得只显示“同步失败”。

## 17. Go/No-Go 决策点

### G1：数据源准入

Canvas API 与学校官网/SIweb 只读爬虫已确定为实施路线。T2、T3 的剩余目标是完成连接参数和契约验证，完成后才能从连接器原型进入正式同步实现。

- Canvas API：必须验证授权、分页、限流、当前用户日期 override、公告和测验类事项字段。
- SIweb 爬虫：必须验证允许的页面范围、会话方式、稳定 ID、选择器契约、请求频率和结构变化检测。
- 任一来源要求绕过 MFA、验证码或访问限制：该方案立即 No-Go。

### G2：日历安全

完成日历身份、EventKit 权限和删除规则的自动化/集成测试后，才能使用真实 iCloud 日历。

### G3：AI 外部数据

只有在数据字段清单、提供方说明、用户同意和确认门禁完成后，才能启用外部 AI。

### G4：第二阶段

只有第一阶段完成七天运行验收后，才能进入 AI 学习指导。

### G5：真实试运行 UI 准入

Stage 10R 的周课表、空间化日历和简体中文系统 UI 必须先经主线程验收。Stage 10 的七天连续计时在此之前暂停；Stage 10R 通过后，从新的完整本地自然日重新开始七天记录。

### G6：DeepSeek 外部处理准入

用户已明确选择先暂停 Stage 10、完成扩展，再用最终版本重跑真实验收。只有在 DeepSeek 提供方说明、当前条款/隐私政策日期、传输字段清单、跨境处理提示、API Key Keychain 保存、显式同意、严格 Schema 和关闭/清理能力全部通过后，才可对真实 Canvas 公告启用外部处理。学校政策禁止外传的内容不得发送。

## 18. 实施顺序

### M0：连接可行性验证

完成 T1–T4 和 G1，先确认合法数据来源、降级方案和统一模型。

### M1：本地应用核心

完成 T5–T6，使用假数据建立可操作界面、数据库、Keychain 和诊断基础。

### M2：确定性同步

完成 T7–T10，建立可靠连接器、规则解析、故障隔离、幂等同步和 Outbox。

### M3：系统集成

完成 T11–T12、T14 和 G2，加入 Apple 日历、通知、安全和诊断。

### M4：AI 增强

完成 T13 和 G3，在稳定的确定性链路之上加入 AI 整理和确认队列。

### M5：真实验收

先完成 T17 和 G5，再完成 T15–T16，验证 iCloud 跨设备同步并从新的完整自然日连续试运行七天。

### M6：外部 AI 公告分类

在已验收 Stage 10R 基线上暂停 Stage 10，依次完成 T18–T19 和 G6。先建立 DeepSeek 提供方/同意/安全边界，再实现 Canvas 公告学习信号分类，不扩展为学习规划。

### M8：最终真实验收

Stage 15 联合验证已验收的 Canvas、SIweb、DeepSeek、日历、通知与隐私范围，冻结最终签名版本。Stage 15 通过后恢复 Stage 10，重新验证真实设备设置；设置日不计入试运行，从下一个完整澳门自然日重新累计七天。此前 0/7 记录不结转。

## 19. 第二阶段：AI 学习指导

第一阶段稳定后，AI 才能根据课表、官方截止时间、已确认建议时间、本地完成状态、预计耗时和用户提供的可用时间提出“现在最应做什么”的建议。

第二阶段仍只提供建议，不自动更改学校系统、Apple 日历或用户完成状态。任何新增的自动计划能力必须单独评审权限、确认和撤销机制。
